## 统一撰写规范（每个文件都遵守）

所有接口文档遵循同一种写作思路，**从阅读者视角出发**——开发者拿到
文档只关心四件事：这个接口解决什么问题？怎么调？传什么参数？会出什么错？

写作层次固定为三层，层层递进：

1. **子项目层**：先介绍这个子项目的作用、定位、什么时候需要用到；
2. **模块层**：逐模块介绍。每个模块先说明作用、定位、什么时候需要用到，
   再进入该模块的接口；
3. **接口层**：逐接口介绍，固定顺序——
   接口作用 → 定义 → 代码演示 → 每个参数的作用与意义（含返回值与错误约定）。

代码演示与接口强相关，接口相关的演示代码一律不省略。
